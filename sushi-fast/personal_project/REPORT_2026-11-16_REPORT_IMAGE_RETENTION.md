# 리포트 원본 이미지 보존 및 대체 전송 조사 — 2026-11-16

## 최신 사용자 정정 및 운영 반영
- 사용자는 전송 성공 및 작성완료 후 사진 삭제가 정상이라고 명확히 확인했다. 보존 후보는 철회하고 기존 완료 시 첨부 정리 및 보류 재시도 경로를 복원했다. 사진 복구는 배포 조건이 아니다.
- 전체 격리 테스트 502개 통과 후 Kakao 프로세스 잠금과 활성 전송 없음 확인하에 로컬 운영 백엔드를 재시작했다. `restart_exit 0`, OpenAPI HTTP 200, 운영 큐 인덱스 `idx_clinic_delivery_dedup_v5`를 확인했다. 사용자 화면 종단 간 동작과 실제 본계정 이미지 수신은 검증되지 않았다.
- 재전송 시 이미 작성완료되어 정리된 첨부는 재생성 PDF에서 빠진다. 이 정리 동작을 유지하며, 과거와 같은 이미지가 자동 복원되지는 않는다.

## 현황
- 작성완료 경로는 기존에 원본 첨부 행과 파일을 삭제했다. 재전송용 PDF 재생성 시 원본 사진이 빠진다.
- 조사 대상 리포트의 완료된 정리 기록은 5개이며 각각 지문이 있다. Spotlight 파일명 검색, `sushisite-runtime-data.tar.gz` 항목 검사, `sushisite-deploy-backups` 파일명 검사에서 일치 원본 0/5. Time Machine 대상이 설정되어 있지 않고 `/`와 `/Volumes/MacWork` 로컬 스냅샷은 확인되지 않았다. 이름이 바뀐 복사본이나 다른 백업까지 없다는 뜻은 아니다. 복원하지 않았다.
- 수동 `cleanup_submitted_batch.py`는 별도 명령 경로다. 이번 조사에서 실행하지 않았다. 학교·회차 삭제 및 사용자의 명시적 첨부 삭제에는 기존 정리 경로가 남는다.

## 후보 수정 및 검증
- 이전에 시험했던 사진 보존 후보는 사용자 정정에 따라 철회했다.
- 대체 발송은 대상 안내 후 PDF에서 만든 이미지를 전송하며, 발송 중 오류는 부분·미확인 상태로 보존한다. 새 요청 ID로 완료 후 재요청하고 동일 ID는 멱등 처리하는 큐 후보도 포함한다.
- `personal_project/tests` 504개 통과(격리 DB/모의 중심). 실제 제품 검증과 다르다.
- 합성 리포트의 본계정 실제 이미지 시험에서 안내문 확인 뒤 이미지 발송 확인이 실패해 `partial`로 반환됐다. 이미지가 도착했을 가능성이 있어 같은 시도를 재전송하지 않았다. 본계정 대화방 열기 동작은 도구가 명시적 비동의로 차단했다. 확인을 우회하지 않았다. 지난 보고의 ‘승인 응답 없이 차단’이라는 표현은 정확하지 않으며 실제 결과는 명시적 비동의다.
- 실제 본계정 이미지 수신, 원래 문제 리포트 재전송과 최종 운영 E2E는 미검증이다.
