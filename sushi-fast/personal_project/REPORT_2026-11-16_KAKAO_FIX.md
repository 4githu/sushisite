# 카카오 리포트 전송 수정 및 검증 — 2026-11-16

## 원인과 수정
- 검색 결과가 실제 창 밖의 접근성 좌표로 반환될 수 있어 해당 좌표를 클릭하는 문제를 수정했다. 정확히 일치하는 후보가 하나인지 매번 재확인하고, 안전한 창 내부에 들어온 뒤에만 클릭한다. 채팅방 확인은 최대 5초 기다린다.
- 본계정 대체 전송에서 긴 메시지는 카카오 접근성 값이 500자까지만 표시되어 실제 표시된 메시지와 전문 비교가 불가능하다는 현상을 확인했다. 대체 텍스트를 350자 이하 메시지로 나누고 각 메시지 발신을 독립 확인한다. 일부만 확인되고 실패하면 `partial`로 보존하여 자동 재발송하지 않는다.
- 서로 다른 리포트의 준비 작업이 서로 삭제되지 않도록 수정했다.

## 검증
- 카카오 도우미 설치 후 본계정 고정 합성 텍스트와 이미지 각각 실제 발송 성공. 합성 이미지→안내문 연속 발송 성공.
- 1,109자 합성 대체 텍스트를 본계정으로 실제 전송: 4개 메시지 모두 발신 확인. 이후 대화방 재조회에서 4개 조각 원문이 각각 일치함을 확인했다.
- 관련 합성 회귀 테스트 93개 통과. 신규 부분 실패 테스트는 확인된 조각 수와 `partial` 상태를 확인한다.
- 설치된 도우미 교체와 로컬 백엔드 재시작 후 OpenAPI HTTP 200 확인. 원격 배포는 확인하지 않았다.

## 실제 대상의 제한
- 대상 428의 운영 API 준비 단계에서 학생 후보 두 방 부재 후 본계정 선택 및 `not_started`를 확인했다. 사용자 승인에 따라 실제 리포트를 본계정으로 별도 시험 발송했으나 당시 긴 텍스트의 발신 확인이 `delivery_unknown`으로 끝났다. 본계정 대화에서 해당 리포트의 발신 방향과 접두부를 확인했으나 접근성 표시가 잘려 전문 일치는 확인하지 못했다. 이 기존 불확실 건을 재발송하지 않았다.
- 위 시험은 직접 백엔드 함수를 호출했으며 운영 서비스의 작성완료 처리를 호출하지 않았다. 수정 후 동일 실제 리포트 전체 전송과 작성완료의 운영 API 종단간 성공은 아직 검증되지 않았다.
- 긴 대체 리포트는 여러 메시지로 표시된다. 이 변경은 실제 검증 오류를 피하기 위한 것이며 부분 전송 시 사람의 확인이 필요하다.

## 새 합성 리포트 앱 종단간 검증
- 운영 앱에서 명시적으로 표시된 합성 학교 24, 회차 323, 대상 453, 리포트 456을 만들고 합성 내용으로 저장했다. 삭제하지 않았으므로 테스트 데이터는 남아 있다.
- 실제 앱에서 '카카오톡으로 받기' 버튼을 클릭했다. 운영 API는 HTTP 200, `sent=true`, `deliveryStatus=verified`, `completionStatus=completed`, 본계정, 텍스트를 반환했다. 앱에도 본계정 텍스트 전송과 전송 완료가 표시됐다.
- 리포트를 API로 다시 조회하여 `submitted` 및 제출 시각이 있음을 확인했다. 본계정 대화방을 별도 재조회해 합성 리포트의 네 텍스트 조각이 모두 정확히 존재함을 확인했다.
- 대상 428은 재전송하지 않았으며 최종 조회 시 `draft`였다. 새 합성 리포트 성공은 기존 건의 실제 전송 확인이나 해결을 증명하지 않는다.

## 기존 대상 추가 확인
- 428에 연결된 영속 예약 큐 및 즉시 전송 요청 기록은 조회 시 각각 0건이다. 이 기록의 부재는 과거 전송이 없었다는 증거가 아니다. 요청 ID 조회의 404는 `deliveryStatus=unknown`, `retryable=false`를 반환한다.
- 이전에 별도로 수행한 본계정 직접 시험의 메시지를 대화방에서 전체보기로 확인해, 현재 리포트의 대체 텍스트 2,254자와 전문이 일치함을 확인했다. 이 시험은 사용자가 화면에서 실행한 과거 요청과 동일하다는 증거가 아니며, 학생 방의 수신 여부도 확인하지 못했다. 기존 건 재전송이나 상태 변경은 하지 않았다.
