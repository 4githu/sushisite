# DSHS 자료공유 연동

대상은 `https://test.dshs.app/board/nSW86Tx`와 NETAQ 자료공유 게시판 4입니다. 공식 DSHS API를 가정하지 않고, 봇 계정으로 로그인한 Chromium이 목록·작성·첨부 화면을 조작합니다. 임의 URL·채팅방을 받는 공개 자동화 서버는 없습니다.

## 실행과 확인

- `ops/dshs_bridge.mjs`: JSON stdin/stdout 브라우저 어댑터.
- `sushi-fast/personal_project/dshs_sync.py`: DB에 처리 이력과 발신 대기열을 저장하는 작업자.
- `ops/app.sushisite.dshs-relay.plist`: Mac launch agent 설정.
- 실행 주기: 한 차례 처리 완료 후 1,800초. Mac이 꺼져 있거나 네트워크가 끊기면 실행할 수 없습니다.
- 최초 실행: 기존 원격 글 ID와 로컬 마지막 글 ID만 기준점으로 저장합니다. 과거 글을 일괄 발송하지 않습니다.
- 다음 실행: 최대 100페이지의 전체 목록을 확인하며, 아직 처리하지 않은 글을 한 번에 10개씩 가져옵니다. 남은 글은 후속 실행에서 처리합니다. 목록 조회가 실패하면 기준점을 갱신하지 않습니다. 조회 전에 삭제된 글은 복구할 수 없습니다.
- 별도 프로세스로 동작하므로 카카오톡의 화면 점검을 막지 않습니다. 파일 잠금으로 작업자의 중복 실행을 방지합니다.

로컬 상태 확인:

```sh
launchctl print gui/$(id -u)/app.sushisite.dshs-relay
```

DB의 `dshs_relay_health`에는 최근 성공/오류 시각, `dshs_relay_state`에는 마지막 스캔과 로컬 기준점, `dshs_relay_outbox`에는 각 발신 결과가 기록됩니다. 관리자 전용 `GET /api/personal/dshs-relay`도 구현되어 있으며, 해당 백엔드 변경 배포 후 사용할 수 있습니다.

## 어댑터 계약

입력 예시(읽기 전용):

```json
{"command":"read","baseline":true,"seen":[]}
```

`baseline:true`이면 글 ID만 가져옵니다. 일반 읽기는 `seen`에 이미 처리한 상대 경로 ID를 넘깁니다. 응답은 `complete`, `ids`, `posts`이며 각 글에는 `id`, `url`, `title`, `text`, `images`, `files`가 있습니다. 본문 이미지는 브라우저가 표시한 PNG 캡처이고, 파일은 다운로드 버튼을 통한 원본입니다. 본문 이미지 원본 품질 보존은 보장하지 않습니다.

게시 입력:

```json
{
  "command":"publish",
  "title":"자료 제목",
  "text":"본문",
  "source":"https://netaq.chobab.app/personal-project/calendar/boards?board=4&post=123",
  "files":["/absolute/path/to/staged-file.pdf"]
}
```

`source`는 지정된 게시판의 글 주소만 허용합니다. 파일은 하나씩 선택하고 업로드 완료를 기다린 뒤 게시합니다. 제목과 출처가 일치하는 게시 결과를 확인해야 `published:true`를 반환합니다. `command:"verify"`는 같은 제목·출처를 조회하며 새 글을 만들지 않습니다(현재 첫 페이지에서 확인).

## 실패와 중복 방지

발신 전에 대기열을 `unknown`으로 기록합니다. 확인된 성공만 `succeeded`가 됩니다. 브라우저가 종료되거나 제출 결과가 불확실하면 **자동 재전송하지 않습니다**. 담당자가 원격 게시판에서 원문 출처를 확인해야 합니다. 화면이 바뀌거나 첨부 제한을 초과하면 누락된 첨부 없이 글만 발송하지 않고 중단합니다.

DSHS에서 가져온 글의 원격 ID와 로컬 글 ID를 매핑해 DSHS로 재전송하지 않습니다. 반대 방향의 글에는 출처 주소를 남겨 순환 전송을 차단합니다. 카카오톡으로의 전달은 기존 자료공유 게시판 연동을 사용합니다.

## 보안

자격 증명은 Git에서 제외된 `sushi-fast/.runtime/dshs-credentials.json`에 `email`, `password` 필드로 보관하며 파일 권한은 600입니다. 명령행 인자·로그·클라이언트 번들에 넣지 않습니다. 브라우저 프로필은 매번 폐기합니다.

NETAQ 가져오기·발신 시 현재 게시판 접근 권한을 다시 확인합니다. 첨부 URL에도 기존 자료 권한 검사를 적용하며, 비공개 자료를 공개 URL로 옮기지 않습니다. 자동화 상태 조회는 관리자만 가능합니다. 명시적 권한 거부는 자동으로 해제하지 않습니다.

DSHS 업로드는 파일당 20MB, 가져오기는 글당 파일 10개·본문 이미지 10개로 제한합니다. 로컬 파일은 실행하지 않으며 비이미지 자료는 다운로드 첨부로 제공합니다. NETAQ 저장소 용량 제한도 적용합니다.

## 2026-10-08 확인 결과

- 로그인 및 2페이지에 걸친 기존 글 36개 목록 수집 성공.
- 테스트 글과 텍스트 파일 1개 게시 성공, 원격 상세 화면에서 첨부 확인.
- 같은 글을 재게시하지 않고 출처로 확인 성공.
- 테스트 첨부파일을 브라우저로 다시 다운로드하는 읽기 흐름 성공.
- 권한·기준점·순환 전송·불확실한 제출의 재시도 방지 자동 테스트 통과.
- 운영 작업자의 첫 기준점 생성 및 오류 없는 완료 상태 확인.

기존 카카오톡 30초 점검과 DSHS 30분 점검은 별개입니다. 카카오톡은 30분 동안 쌓인 모든 대화를 읽는 검증이 아직 끝나지 않아 주기를 변경하지 않았습니다.
