# Re:hear 홈·템플릿·웹 리포트·음성 훈련 구현

대상은 실제 서비스 `/odi`다. VR 리포트와 `/odi/GITA` 시제품은 변경 대상에서 제외했다.

## 구현한 동작

- 템플릿 목록 `/odi/templates`: 전체/즐겨찾기, 발표/면접, 검색, 최근 사용/사용 횟수 정렬, 페이지 이동, 설정 상세창. `/odi/favorites`는 리다이렉트한다.
- 템플릿 기본 환경에는 자료, 스크립트와 슬라이드 구간, 환경과 청중을 저장한다. 기존 환경의 세션별 수정은 같은 ID를 사용한다. 명시적인 기본 환경 저장만 버전을 올린다.
- 새 환경 저장과 세션 준비 요청은 요청 ID/해시로 재요청을 구분한다. 다른 내용의 동일 요청은 409를 반환한다. 기본 환경 저장 시 `expected_version`으로 충돌을 검출한다.
- 준비 시 `pre_sessions.template_snapshot`을 동결한다. Firebase 전달, EVC 실행 옵션·자료, 완료 세션과 리포트 복구가 이 실행 설정을 사용한다. 같은 PIN 완료 재요청은 처음 완료한 세션을 반환한다.
- 예전 템플릿 ID, 즐겨찾기 설정, 세션 설정과 피드백 JSON은 유지한다. 동명 환경의 ID를 병합하지 않는다. 과거 사용 횟수와 최근 사용 시각은 기존 세션에서 보완한다.
- 저장된 환경, 진행 중 PIN, 과거 세션이 참조하는 자료는 임시 저장소 정리에서 보호한다. 임시 업로드는 복사하여 저장하므로 실패 후 재시도할 수 있다. 만료된 자료는 재업로드 안내를 반환한다.
- 홈은 기록이 없는 사용자의 사용 안내와 기록이 있는 사용자의 최근 3회, 평균·강점, 최근 5회 E/V/C 추이, 추천 훈련을 구분한다. 다시 연습하기는 해당 회차의 설정과 원래 템플릿 ID를 불러온다.
- 웹 리포트는 템플릿 ID별 주제 탭과 전체 기록 탭을 제공한다. 전체 완료 기록에서 통계를 계산하고, 검색은 통계에 영향을 주지 않는다. 0점과 미측정을 구분하며 200개 이후의 기록도 페이지 단위 API 요청으로 가져온다.
- 면접 준비 화면의 임시 로그 동작도 실제 자료 업로드, 청중 저장, PIN 준비 흐름에 연결했다.

## 스크립트 검사

`POST /odi/coaching/script/check`는 전체 텍스트, 원문 버전, 선택적인 PDF 경로와 수동 슬라이드 구간을 받는다. AI는 PDF 페이지를 참고해 원문 구간과 네 범주의 수정을 제안한다. PDF를 읽을 수 없어도 전체 검사는 가능하다.

문장 범위를 서버가 제공하고 AI 응답의 원문 일치, 범위 중첩, 슬라이드 경계를 검증한다. 자동 분배의 모든 구간을 다시 합치면 원문과 같아야 한다. 브라우저는 Unicode 코드포인트로 제안을 적용하며 원문 또는 슬라이드 버전이 바뀌면 오래된 제안을 적용하지 못한다. 선택/전체 적용, 직접 편집, 구간 추가·순서 이동, 재검사를 지원한다. 적용은 현재 초안만 바꾼다.

AI는 기존 OpenAI 구조화 응답과 서버 설정을 사용한다. `OPENAI_COACHING_MODEL`을 지정하지 않으면 기존 `OPENAI_QUESTION_MODEL`을 사용한다. 문장 편집 검증에서 기본 경량 EVC 모델이 제안을 생략하는 현상을 확인해, 기존 질문 생성 모델과 문장 범위 정보를 사용하도록 했다. 작성한 예문의 실제 호출에서 유효한 수정 제안 2개와 원문 보존을 확인했다.

## 웹 음성 훈련

- 내용: 메시지 명확성, 구조와 흐름, 근거 활용, 주장·근거 연결, 어휘와 표현.
- 전달: 발화 속도, 습관어, 시간 운영.
- 시선과 발음 정확도는 준비 중이며 추천·점수·진도에서 제외한다.
- 과제 선택 → 목표 확인 → 녹음 → 재생/분석 → 결과/재도전. 한국어, 기본 60초, 최대 180초. 웹에서는 AudioWorklet으로 모노 PCM을 수집하고 16kHz WAV로 변환한다.
- 녹음 원본은 현재 화면에서만 재생한다. 서버는 원본을 영구 파일로 저장하지 않으며 분석 후 메모리 참조를 해제한다. 별도 `practice_attempts`에 전사, 점수, 피드백, 상태, 요청 해시를 저장한다.
- 내용 훈련은 과제별 기준과 실제 발화 인용을 평가한다. 전달 훈련은 분당 어절 수(80~160 기준), 습관어 비율, 목표 대비 실제 시간을 계산한다. 발화 속도는 어절 기준이며 음절/음소 평가가 아니다.
- 같은 훈련에서 80점 이상 3회마다 1레벨, 최대 5레벨이다. 주간 목표는 한국 시간 월요일 00:00부터 80점 이상 5회다. 실패·중복 요청·준비 중 훈련은 집계하지 않는다.
- 기존 EVC와 동일한 단일 프로세스 운영을 전제로 한다. 재시작으로 중단된 작업은 실패 상태로 복구하고 현재 화면의 녹음으로 재시도한다. 화면을 닫아 원본이 없으면 다시 녹음한다.

## 검증

- `npm run check`: 오류 0, 경고 0.
- 공식 Svelte autofixer: 변경 컴포넌트 29개, 문제/제안 0. 로컬 검사만 수행하고 네트워크는 고정 문서 목록 GET으로 제한했다.
- 프런트 단위 테스트: 점수/통계/그룹, Unicode 제안 적용과 충돌, WAV 인코딩, 환경 저장/준비 동시 실행 방지 9개 통과.
- Playwright: 기존 PIN·상세 리포트 회귀와 신규 화면 총 27개 통과. 1440/820/390px, 신규 사용자, 전체 기록 205개, 동명 ID 분리, 저장만 수행, 오래된 제안 차단, 가상 마이크 녹음/재생, 권한 거부, 분석 실패/재시도를 포함한다.
- 백엔드: 템플릿·스냅샷·기존 EVC/리포트·미디어·코칭 회귀 테스트 156개 통과. 기존 라이브러리의 Starlette 사용 중단 예정 경고 1건이 있다.
- 실제 계정의 홈, 템플릿, 리포트 UI를 확인했다. 기존 DB 복사본에 마이그레이션을 2회 적용한 뒤 템플릿 98개, 세션 42개, 사용자 5개의 설정과 기존 JSON 해시가 동일함을 검증했다. 복사본은 검증 후 제거했다.
- 로컬 DB를 별도 백업하고 개발 백엔드를 재시작해 실제 DB에도 마이그레이션을 적용했다. 기존 개수는 그대로 유지되며 준비 세션 87개의 실행 설정을 보완했다. 실제 계정으로 새 훈련 API와 목록·진행도 표시를 확인했다.
- `npm run build`: 성공.

## 실행 설정과 남은 실연동 확인

현재 로컬 `sushi-fast/.env`에는 Azure Speech 설정이 없다. 따라서 실제 음성 인식/내용 평가의 외부 서비스 연동은 아직 검증하지 못했다. UI 녹음·재생은 가상 마이크로, 분석·중복 방지는 모킹/격리 DB로 검증했다.

실제 리소스의 `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`을 서버 환경에 설정하고 재시작하면 기존 Azure 연속 인식 어댑터를 사용한다. Fast 모드를 쓰는 기존 환경에서는 `AZURE_STT_MODE=fast`와 `AZURE_SPEECH_ENDPOINT`도 필요하다. 비밀값을 저장소에 커밋하지 않는다.

변경은 로컬 작업 트리에 있으며 운영 배포는 수행하지 않았다. 스키마는 기존 시작 경로 `ensure_report_schema()`에서 추가 마이그레이션하며, 기존 ID나 피드백을 재작성하지 않는다.
