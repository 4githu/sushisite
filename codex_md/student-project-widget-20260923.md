# 학생 서비스·프로젝트·위젯 변경 및 연동 검토 — 2026-09-23

현재 작업 폴더에 구현한 변경이다. 운영 배포·서비스 재시작·운영 DB 변경은 수행하지 않았다. 기존 미커밋 작업을 보존했다.

## 구현된 사용자 흐름

- 일반 회원가입에 학생 여부·학교·학과 입력 추가. 기존 계정과 Google 가입 계정은 캘린더의 **학생 서비스**에서 설정한다. 학생 기능은 선택 사항이다.
- 학교와 무관하게 수업의 요일·시각·강의실을 입력하고, 학기 시작/종료·추가 휴강일을 지정한다. 기본 학기는 3~6월/9~12월이다. 한국 공휴일·대체공휴일은 `holidays`의 KR 자료로 제외한다. 임시공휴일·학교 휴일은 직접 추가할 수 있다.
- 등록 전 생성 일정과 제외 날짜를 미리 확인한다. 입력 변경 시 재확인해야 등록된다. 동일한 입력의 재전송은 중복 생성하지 않는다. 다른 입력은 별도 가져오기이므로 이미 등록한 시간표의 종강일을 자동으로 재조정하는 기능은 아직 없다.
- 서울대에는 생협 공식 식단 링크를 제공한다. 다른 학교에는 학식 미지원 안내를 표시한다. 식단을 앱 내부에 수집·저장하는 기능은 아직 없다.
- 학과 이수규정은 입학 연도·주/복수/부전공별로 사이트 검토본과 사용자 편집본을 분리한다. 새 버전은 추가 기록하고 동시 수정은 409로 거절한다. 원문은 일반 텍스트로 렌더링한다. 공식 학교 인증이나 졸업 판정은 제공하지 않는다.
- 검토본 발행 권한은 서버 환경변수 `STUDENT_CURRICULUM_EDITORS`에 쉼표로 지정한 사용자 ID에만 있다. 기본값은 아무도 발행할 수 없음이다. 실제 공식 규정 데이터 적재와 정기 갱신 작업은 아직 연결하지 않았다.
- 학과 게시판과 날짜가 있는 학과 소식 등록, 내 캘린더로 중복 없이 추가, 본인 글 삭제(서버에서 숨김)를 제공한다. 학교/학과는 자기 신고 정보이며 재학 인증된 비공개 공간이 아니다. 게시판 일정을 개인 캘린더에 추가한 뒤에는 개인 복사본으로 관리한다.
- 프로젝트 관리 화면에서 이름·상위 프로젝트·할 일 분리 표시를 설정한다. 상위 프로젝트 필터는 하위 프로젝트를 포함한다. 순환 관계 및 다른 소유자의 프로젝트를 상위로 지정하는 것을 차단한다. 상하위 관계는 다른 프로젝트의 접근 권한을 자동으로 부여하지 않는다.
- 할 일은 시간순/테마별 전환하며 선택을 브라우저에 기억한다. 분리된 프로젝트와 기존 아우라 할 일은 별도의 접힌 영역으로 표시한다. 상위 프로젝트의 분리 설정도 현재 사용자가 볼 수 있는 하위 프로젝트에 적용한다.
- 일별 메모의 체크박스 추가 버튼, Enter 자동 이어쓰기, 빈 항목 Enter로 종료. 아우라와 동일한 `PersonalTextEditor`를 선택해서 사용할 수 있으며 서식 도구는 접을 수 있다. 기존 텍스트 메모를 자동 변환하지 않는다. 서식과 체크 상태도 서버에 저장한다.
- 펜 도구에 색 선택·지우개·전체 삭제 확인을 추가한다. Pointer Events의 지우개 신호(button 5/buttons 32) 및 펜 보조 버튼(buttons 2)을 지우개로 처리한다. 실제 Surface/S Pen 드라이버별 동작은 실기기 확인이 필요하다.

## 외부 프로젝트 API

기존 아우라의 리포트/완료 판정은 아우라 내부 기능으로 유지한다. 다른 서비스가 캘린더와 연결될 수 있도록 공통 입력 API를 추가했다. 아우라의 모든 내부 코드를 새 외부 API로 이전한 것은 아니다.

1. 프로젝트 소유자가 **프로젝트와 연결 → 외부 프로젝트 API 연결**에서 연동 이름과 키를 발급한다. 서버는 키의 해시만 저장하고 원문은 발급할 때 한 번만 반환한다.
2. `PUT /api/personal/calendar/integrations/events/{external_id}`에 `Authorization: Bearer <연동 키>`를 보낸다. JSON은 기존 EventCreate와 같은 형태다.
3. 최소 필드: `title`, `start_time`. 추가: `end_time`, `description`, `location`, `web_url`, `status`(passive/todo/done), `task_available_from`, `task_due_at`. 시간에는 UTC 오프셋을 명시한다.
4. 요청의 project_id/type으로 권한을 바꿀 수 없다. 키를 발급한 프로젝트로만 들어간다. 같은 연동 키와 external_id는 기존 일정을 갱신한다.
5. `DELETE`의 같은 경로는 해당 연동이 생성한 일정만 삭제한다. 일반 캘린더에서는 연결 일정이 읽기 전용이다. 완료는 원본 서비스가 `status=done`으로 전송한다.
6. 소유자는 연동 키를 해제할 수 있다. 이미 가져온 일정은 남으며 키를 재발급/교체하는 별도 흐름은 아직 없다.

요청 예시(실제 키를 저장소에 적지 않는다):

```json
{
  "title": "동아리 발표 준비",
  "start_time": "2026-10-01T18:00:00+09:00",
  "end_time": "2026-10-01T19:00:00+09:00",
  "status": "todo",
  "web_url": "https://example.org/events/meeting-42"
}
```

## Android 설치 파일과 위젯

기존 APK도 AndroidManifest, DEX, 리소스를 포함한 유효한 설치 파일이었다. APK 자체는 ZIP 컨테이너이지만 압축을 풀어서 설치하는 파일이 아니다. `.apk.zip`이 된 원인이 브라우저/파일 전달 중 어느 단계인지는 재현하지 못했다.

새 다운로드 경로 `/downloads/android-widget`는 `application/vnd.android.package-archive` 및 `attachment; filename="ondo-widget.apk"`를 명시한다. SvelteKit의 번들 에셋 읽기를 사용해 배포 시 작업 디렉터리에 의존하지 않는다.

- Android 8+ 테스트 APK v1.1.0, versionCode 2, debug 서명.
- 다음 일정/일간/주간/월간/할 일 위젯 선택과 홈 화면 고정. 월간은 날짜 격자·일정 수, 목록형은 최대 4개와 전체 개수·웹앱 이동을 제공한다.
- 월간 날짜 선택은 해당 날짜의 웹 일별 화면으로 이동한다. 학교 서비스 기준과 일관되게 위젯의 날짜 기준은 Asia/Seoul이다.
- 앱에서 일정 알림을 켜면 Android 13+ 알림 권한을 요청한다. 거절하면 설정도 꺼진다. 예정된 시간 지정 일정의 시작 약 10분 전에 로컬 알림을 예약한다. 종일 일정은 알림 예약에서 제외한다.
- 30분 주기 백그라운드 갱신과 절전 허용 알람을 사용한다. 정확한 정시 알람을 보장하지 않으며 절전 상태에서 늦을 수 있다. 변경·삭제한 일정이 반영되기 전에는 이전 알림이 남을 수 있다.
- 연결 해제 시 이 기기의 예약 알림을 취소한다. 재연결 시에도 이전 예약을 취소한다.
- 산출물: `sushi-app/static/downloads/ondo-widget.apk`와 같은 파일의 번들용 복사본 `sushi-app/src/lib/server/assets/ondo-widget.apk`.
- `assembleDebug lintDebug`, APK v2 서명 검증 통과. 연결된 Android 기기/에뮬레이터가 없으므로 설치 후 런처·알림 전달은 미검증이다. Play Store용 release 서명/배포는 하지 않았다.

## Class Checker 조사

[공개 데이터 디렉터리](https://github.com/Rekhet/class-checker/tree/main/data)는 강의(`classes`), 수강 추이(`trend`), 탐색 인덱스, 이수규정(`grad_req`)을 분리한다. 확인 당시 강의·추이 데이터에는 최신 `chore(data): update` 커밋이 있었다. 공개 트리에서 전체 수집 실행 환경과 스케줄러까지 확인한 것은 아니므로 우리 서비스의 자동 수집기로 바로 복제할 수 있다고 단정하지 않는다.

[규정 출처 문서](https://github.com/Rekhet/class-checker/blob/main/data/grad_req/SOURCES.md)에 따르면 학과별 HTML/PDF에서 규정을 조사해 학과·학번별 JSON으로 정리한다. 주전공/다전공 병행/복수/부전공에 따라 학점과 필수 과목 집합을 나누고, 교양 영역 어댑터·구/신 과목 코드 대응·타과 인정 조건을 별도로 관리한다. 일부 영역 조건과 인정 상한의 근사/미반영도 문서에 명시되어 있다. 따라서 참고 데이터와 학교의 공식 졸업 판정은 구분해야 한다.

권장 갱신 방식은 원문 URL·적용 학번·전공 유형·수집일·검토자를 보존하고, 주기적으로 원문 변경을 감지해 검토 후 새 사이트 버전을 발행하는 방식이다. 사용자 편집본은 이 갱신으로 덮어쓰지 않는다. 이 주기 수집/검토 작업은 아직 구현하지 않았다.

[설정 파일](https://github.com/Rekhet/class-checker/blob/main/config.js)은 검색 기본 연도/학기와 ICS 내보내기 시작·종료일을 별도로 둔다. 우리 서비스도 학기 기간을 명시적으로 선택하는 방식을 사용한다.

## SNUTT·에브리타임

[SNUTT 저장소](https://github.com/wafflestudio/snutt)는 서울대 수강편람 검색/시간표 API 서버다. 다른 학교 전체를 자동 지원하는 공통 API가 아니다. 저장소가 공개되어 있어도 사용자 시간표를 임의로 읽을 수 있는 것은 아니다.

[에브리타임](https://everytime.kr/)의 외부 앱용 공식 시간표 가져오기 API는 이번 조사에서 확인하지 못했다. 비공식 API를 이미 지원하는 것처럼 표시하지 않았다.

현재는 학교 공통 수동 입력 경로를 제공한다. 실제 ‘내 시간표 가져오기’ 검증에는 사용자가 제공할 테스트 공유 링크 또는 제공자가 지원하는 인증/내보내기 방식 확인이 필요하다. SNUTT/에브리타임 자동 연동은 미구현·실데이터 미검증이다.

## Google Calendar 현재 방식과 개선 제안

현재 `google_calendar.py`는 여러 계정·선택 캘린더, 서버 5분 주기 동기화, 로컬 일정의 명시적 내보내기, ETag 충돌 보호를 구현한다. 지난 1년~향후 2년을 조회하고 반복 일정을 개별 발생 일정으로 가져온다. Google Tasks와 Gmail을 연결한 것은 아니다. 이 동기화 엔진은 이번에 변경하지 않았다.

권장 방향:

1. 초기 전체 동기화 이후 캘린더별 `syncToken`을 저장해 변경분만 조회한다. 페이지 전체 처리와 토큰 저장을 하나의 성공 경계로 묶고, 410 응답 시 재동기화하되 앱 원본은 보존한다. 시간 범위가 이동하면서 새로 들어오는 반복 발생 일정의 보충 조회도 설계해야 한다. [Google 증분 동기화](https://developers.google.com/workspace/calendar/api/guides/sync)
2. 운영 규모가 늘면 watch/webhook을 붙여 변경 시 동기화를 예약하고 주기 조회는 복구용으로 유지한다. webhook 자체에는 이벤트 본문이 없으므로 반드시 변경분 조회가 필요하며, 채널 만료 전에 재등록해야 한다. [Google 푸시 알림](https://developers.google.com/workspace/calendar/api/guides/push)
3. UI에서는 읽기용 가져오기/양방향 연결/내보내기를 구분하고, 프로젝트별 목적 캘린더를 명시한다. 알림의 담당 앱도 사용자가 선택하게 해 Google 알림과 자체 앱 알림이 겹치지 않게 한다.
4. 장기적으로 반복 규칙(RRULE)·예외·원본 UID를 보관한다. 시간표를 개별 일정으로만 늘리는 현재 구조에서 이후 학기 변경·휴강·Google 왕복 수정이 어려운 부분을 해결한다.

## 메일 알림 제안

학생 전용이 아닌 공통 **알림 모음**으로 두는 것이 적합하다. 카테고리별로 사용자가 발신자·제목 키워드·학기(예: 2026-2)·날짜 범위를 편집하고, 일치 결과 미리보기 → 저장 흐름을 둔다. 메일 ID로 중복을 방지하고 원문 링크를 제공하며 자동 발송/답장은 하지 않는다.

Gmail은 메시지 검색의 `q` 매개변수를 지원한다. 읽기 권한을 별도로 동의받아야 하며, 현재 Calendar OAuth 승인만으로 메일을 읽을 수 있다고 간주하면 안 된다. Outlook/학교 메일은 공급자별 연결 방식이 필요하다. 이번에는 OAuth·메일 수집 기능을 구현하지 않았다. [Gmail 검색·필터 문서](https://developers.google.com/workspace/gmail/api/guides/filtering)

## 검증

- 임시 DB에서 백엔드 테스트 20개 통과: 프로젝트 권한·순환, API 키 범위/폐기·중복 갱신, 시간표 공휴일/중복 방지, 위키 충돌/발행 권한, 게시판 학과 범위/캘린더 중복 방지 등.
- 웹 캘린더 E2E 12개 통과: 기존 일정/아우라, 모바일, 일별 메모·서식 저장/재조회, 학생 시간표 미리보기, 위키·게시판, APK 다운로드 헤더.
- Svelte check 오류/경고 0. 프로덕션 빌드 통과. 프로젝트가 언급한 Svelte MCP는 제공되지 않아 컴파일러와 브라우저 테스트로 대체.
- 최종 펜 입력·실제 픽셀 삭제 및 서식 재조회 검증 2개 추가 재실행 통과.
- 데스크톱/모바일 스크린샷 확인. Android 실기기와 실제 외부 계정 연동은 미검증.
