# 온도 캘린더 디자인 진단 및 개편

## 진단

이 화면에서 느껴지는 ‘AI가 만든 듯한 디자인’은 특정 색 하나의 문제가 아니라 아래 선택이 겹친 결과로 판단했다. AI 제작 여부를 판별하는 기준이 아니라 현재 제품에 대한 디자인 진단이다.

| 기존 문제 | 사용 경험에 미치는 영향 | 이번 변경 |
|---|---|---|
| 종이색 배경, 초록 버튼, 푸른 테두리와 텍스트가 혼재 | 무엇이 하나의 제품인지 불분명 | 차콜 탐색 영역 / 차가운 중성 작업면 / 주홍색 주요 동작으로 역할 구분 |
| 버튼마다 비슷한 테두리·크기 | 일정 생성, 기간 이동, 필터의 중요도 구분이 약함 | 생성은 채워진 버튼, 기간 이동은 아이콘, 검색·필터는 낮은 대비의 보조 도구 |
| 작은 보조 글씨와 기호 문자를 아이콘으로 사용 | 임시로 조립된 화면처럼 보이고 식별 어려움 | 일정·날짜·설명 글자 단계 정리, 같은 굵기와 크기의 SVG 아이콘 |
| 라운드 박스와 장식 영어가 반복 | 실사용 정보보다 스타일 장치가 눈에 띔 | 불필요한 영문 장식 제거, 표·구분선 중심의 구조, 일별 계획만 한 패널로 묶음 |
| 탐색 영역이 항상 같은 폭을 차지 | 작은 창에서 시간표가 좁아짐 | 232px 사이드바 ↔ 72px 아이콘 레일, 선택 상태 저장 |
| 모바일에 데스크톱 메뉴를 그대로 나열 | 일정이 화면 아래로 밀림 | 1줄 상단 바와 접을 수 있는 메뉴, 클릭 후 자동 닫힘 |
| 월간 화면 항상 6주 생성 | 필요 없는 다음 달 날짜와 빈 영역 | 해당 월에 필요한 주 수만 렌더링 |

## 기준과 참고 자료

- NN/g, [Good Visual Design, Explained](https://www.nngroup.com/articles/good-visual-design/): 정렬된 그리드, 글자 위계, 의도적인 색 사용, 일관성. 이 원칙을 날짜·본문·보조정보와 도구 모음의 우선순위에 적용했다.
- IBM Carbon, [Color overview](https://carbondesignsystem.com/elements/color/overview/), [Color tokens](https://carbondesignsystem.com/elements/color/tokens/): 색에 역할을 부여하고 재사용하는 체계. 실제 팔레트를 복사하지 않고 배경·본문·보조 텍스트·경계·동작 토큰으로 분리했다.
- GOV.UK, [Colour](https://design-system.service.gov.uk/styles/colour/): 기능별 색의 일관성. 오늘은 주홍색과 날짜 원형, 선택 메뉴는 배경과 세로 표식, 완료는 체크와 취소선으로 표시해 색에만 의존하지 않았다.

## 적용 범위

온도 캘린더의 월·주·일·할 일·연결 화면과 일정 편집창. 전용 `calendar-shell.css`로 서비스 외곽을 분리해 아우라의 별도 화면을 유지한다. 사이드바는 로컬 저장소를 이용해 접기 상태를 기억하며 저장소를 사용할 수 없어도 조작할 수 있다. 모바일은 별도 메뉴 열림 상태를 사용한다.

색 역할: 차콜 `#232428`, 작업 배경 `#f4f5f7`, 일정 표 `#ffffff`, 본문 `#25262b`, 보조 텍스트 `#6b6e78`, 주요 동작 `#bf402d`. 일정의 분류 색상은 구분을 위한 제한된 팔레트로 유지한다.

배포는 수행하지 않는다. 화면 캡처는 실제 사용자 데이터가 아닌 테스트 데이터로 검증한다.

## 검증 결과

- `npm run check`: 오류 0, 경고 0.
- `npm run build`: 성공.
- Playwright 캘린더 E2E: 8개 통과. 일정 생성·수정·삭제, 아우라 이동, 필터, 일별 메모·자정 이후 일정, 종일 행 고정, 사이드바 접기 상태 유지·화면 이동·모바일 메뉴 검증.
- 월간·일별·접힌 주간·모바일 화면 직접 확인. 390px 화면 가로 넘침 없음.
- 작업 지침이 지정한 Svelte MCP 도구는 세션에 제공되지 않아 Svelte 컴파일러·타입 검사 및 실제 브라우저로 검증.
