# NETAQ 안정성 및 Rehear 성능 개선 — 2026-09-22

## 운영 적용
- 기존 Cloudflare 터널과 도메인을 유지했다. 프런트엔드 launchd를 Vite 개발 서버에서 adapter-node 프로덕션 빌드로 교체했다.
- 실행 파일: `sushi-app/scripts/serve-production.mjs`. 기존 백엔드 API 경로, 업로드 및 SSE는 스트리밍 프록시로 유지한다.
- 운영 plist 원본 백업: `ops/app.sushisite.frontend.before-20260922.plist`; 현재 설정: `ops/app.sushisite.frontend.production.plist`.
- 백엔드 DB 백업: `/private/tmp/netaq-before-20260922.db`.

## 변경
- 달력 루트에 잘못 적용된 fixed 위치를 제거하고 사이드바/본문 그리드 열을 명시했다.
- 모바일 일별 화면에서 할 일·메모 / 시간표 전환, 입력 글자 크기 및 터치 영역을 개선했다.
- 주 로그인과 Rehear 사용자 로그인 유효기간을 30일로 맞췄다. 유효한 주 로그인은 잔여 7일 미만이면 갱신한다. 이미 만료된 로그인은 다시 로그인해야 한다.
- 중복 인증 요청을 합치고, 서비스 워커는 해시가 붙은 정적 코드만 캐시한다. 개인정보 API와 인증 응답은 캐시하지 않는다.
- 공통 이벤트 모델에 작업 가능 시작일, 마감일, 완료 상태 출처를 추가했다. 시작 전 작업은 별도 접힌 목록으로 표시한다.
- 아우라 연동은 SQLite 어댑터 및 트리거에서 제출 상태를 일반 이벤트 상태에 반영한다. 출석 완료만으로 보고서 완료를 처리하지 않는다.
- 기존 완료 이벤트 85건을 복구했다. 외부 연동 이벤트 done 85건 / todo 60건이며 원본과 상태 불일치 0건, DB quick_check 정상이다.
- 아우라 보고서는 일정 시작부터 수행 가능하고 3일 후 마감이다. 기존 연결 URL이 비어 있으면 클리닉 페이지 URL을 채운다.

## 미적용 제안
Rehear는 전체 세션 기록을 가져온 뒤 성장 통계와 추천을 계산한다. 최근 기록부터 표시하고 과거 기록·통계를 뒤에서 불러오면 기록이 많은 계정의 첫 화면을 더 빠르게 표시할 수 있다. 다만 통계가 나중에 완성되는 동작 변경이 생기므로 사용자 승인 전에는 적용하지 않는다.

## 프런트엔드 롤백
필요하면 백업 plist를 `~/Library/LaunchAgents/app.sushisite.frontend.plist`로 복원하고, 로그인 사용자 GUI 도메인에서 launchctl bootout 후 bootstrap 한다. 이 변경은 프런트엔드 실행 방식만 되돌린다. DB 백업 복원은 이후 작성된 데이터를 잃을 수 있으므로 자동으로 하지 않는다.
